LIVE LAYER PROTOCOL

How new code gets into
a running app

The app is split into small layers. One layer can be replaced while the app runs, and only after it has been checked.

1
The AI changes one layer

Each layer is a small WebAssembly module: the task list, the footer… The AI rewrites only the one that needs to change.

2
Tested before anyone sees it

It's compiled, then run on a copy of realistic app data with every button clicked. A crash or an endless loop sends it back to the AI.

bug stops here
3
Signed and streamed

A person approves, then the release is signed and streamed to running apps. Devices refuse unknown keys, altered code and older versions.

4
Swapped in milliseconds

The device checks it once more on a shadow copy, then swaps it in. No restart. If the new layer crashes later, the device rolls back by itself.
